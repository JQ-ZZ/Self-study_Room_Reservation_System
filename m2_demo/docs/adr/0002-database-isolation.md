# ADR-0002：一个 PostgreSQL 实例，三个独立数据库

- 状态：提议
- 日期：2026-10-21
- 决策者：A / B / C（待确认）

## 背景

任务书要求模块通过公开接口协作，附加项也把「直接访问其他模块数据库」列为未完成。
但三个服务各自维护一台数据库实例，对课程项目和单机部署来说成本过高。

## 决策

1. 一个 PostgreSQL 容器/实例。
2. 每个模块一个数据库：`m1_db`、`m2_db`、`m3_db`（认证服务可再分 `auth_db`）。
3. 每个服务只拿到自己数据库的连接串，账号无跨库权限。
4. schema 变更由各模块自己的 Alembic 迁移链管理，部署时按 m1 → m2 → m3 顺序执行。

## 理由

- 数据库级隔离让「直接查别人库」无法实现，符合架构要求。
- 单实例降低资源占用，仍然可以通过权限和连接串证明隔离。
- 各模块迁移互不阻塞，合并到同一部署脚本执行。

## 代价

- 无法做跨库事务；跨模块一致性必须依赖 outbox、重试或补偿。
- 备份/恢复需要按库分别处理。

## 备选方案

- 一个库三个 schema：实现更简单，但隔离性弱，容易出现跨 schema 查询。
- 三个独立实例：隔离最强，单机资源成本高。
