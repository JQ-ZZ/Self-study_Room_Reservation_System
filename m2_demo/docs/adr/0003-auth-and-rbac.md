# ADR-0003：认证与授权边界

- 状态：提议
- 日期：2026-10-21
- 决策者：A / B / C（待确认）

## 背景

公共层 D 由成员 C 负责认证与 RBAC。M2 需要「无权限用户不能申请或审批」，
但不应重复实现登录系统。

## 决策

1. C 的认证服务负责登录、签发 JWT。
2. JWT 使用非对称签名（推荐 RS256），公钥分发给 M1/M2/M3 本地验签，避免每个请求回调认证服务。
3. JWT 至少包含：`sub`、`name`、`roles`、`iat`、`exp`。
4. M2 在接口层再次校验角色（`student/teacher` 可申请，`approver_l1/approver_l2` 可审批），不能只依赖前端隐藏。
5. 演示阶段 M2 内置 `POST /api/v1/auth/login` 和 HS256 验签，仅用于原型；接入 C 后删除演示登录，只保留验签逻辑。

## 理由

- 认证服务故障不应导致所有业务接口不可用。
- 角色校验放在业务服务内，符合「接口真正检查权限」的要求。

## 待确认

- 角色命名与 C 的 RBAC 矩阵是否一致。
- 服务间调用使用用户 token 还是独立的服务凭证。
- token 过期与刷新策略。
