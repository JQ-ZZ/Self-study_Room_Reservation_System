# M1 ↔ M2 接口契约（v0.2）

日期：2026-10-21
状态：已按成员 A 的 M1 demo（PR #1）对齐；M1 提供实现，M2 为调用方
变更：v0.1 的 `/api/v1/rooms`、`/api/v1/occupancies` 方案未采用，改为 A 已实现的 `/api/meta` + `/api/integrations/restrictions`

---

## 1. 原则

1. 跨模块只走 HTTP，不读对方数据库。
2. 所有写接口必须**幂等**：同一个 `(source, external_id)` 重复调用结果一致。
3. M1 不能用 2xx 掩盖失败；M2 也不得把“写成功”当成“已生效”，必须检查响应语义。
4. M1 的 demo 只接受**北京时间、不带时区后缀**的时间字符串，例如 `2026-10-22T09:00:00`。
   M2 内部统一存 UTC-naive，在 `M1Client` 边界完成转换；这是 v0.2 的临时方案。
5. 认证当前为演示头 `X-Demo-User: admin`，客户端可伪造；正式版必须替换为 C 的公共认证/服务 token。

---

## 2. 教室主数据

### GET `/api/meta`

无需认证。M2 用它校验教室是否存在、取教室名称/区域/开放时间。

```json
{
  "now": "2026-10-21T20:00:00",
  "rooms": [
    {"id": 1, "name": "明德楼 201", "area": "安静区", "opens": 8, "closes": 23, "active": 1}
  ],
  "demo": true
}
```

- `id` 是**整数**；M2 API 对外仍用字符串，适配层负责 `int ↔ str`。
- M2 当前只使用 `id / name / area / opens / closes / active`，不依赖 `capacity`。

## 3. 座位可用性（M2 冲突预检）

### GET `/api/seats?start=...&end=...&room_id=1&outlet=false`

时间参数为北京时间 naive。返回该教室的座位数组：

```json
[
  {
    "id": 1,
    "room_id": 1,
    "label": "01",
    "outlet": 1,
    "active": 1,
    "room": "明德楼 201",
    "area": "安静区",
    "opens": 8,
    "closes": 23,
    "room_active": 1,
    "sources": ["M1:个人预约"],
    "available": false
  }
]
```

`sources` 的取值约定：

| 值 | 含义 |
|---|---|
| `M1:个人预约` | 该座位已有个人预约 |
| `M2:<external_id>` | 整教室被 M2 申请占用 |
| `M3:<external_id>` | 整教室被 M3 维修限制 |
| `管理员停用` | 教室或座位被停用 |
| `非开放时间` | 请求时段超出开放时间 |

M2 在**二级审批通过前**调用该接口做只读预检：

- 任一座位出现 `M1:个人预约`、`M2:*`、`M3:*` → 返回 409，申请保持 `PENDING_L2`；
- M1 返回 5xx/网络错误 → 不阻塞审批，继续写入 outbox，由后台重试；
- 预检与 outbox 执行之间仍有竞态，占用接口返回 409 时 M2 将同步记录置为 `DEAD` 并展示错误。

## 4. 占用整间教室（M2 → M1）

### POST `/api/integrations/restrictions`

请求头：`X-Demo-User: admin`（演示专用）

```json
{
  "source": "M2",
  "external_id": "8f1c...",
  "room_id": 1,
  "start": "2026-10-22T14:00:00",
  "end": "2026-10-22T16:00:00"
}
```

- `external_id` 使用 M2 的 `application_id`，`source` 固定 `M2`。
- 时间必须为北京时间 naive，且 `end > start`。

响应：

| 状态码 | 含义 | M2 处理 |
|---|---|---|
| 200 | 新建成功，或同参数重复调用返回已有记录 | 成功 |
| 200 + `active=0` | **A 当前实现的陷阱**：编号已解除，未重新生效 | 视为永久失败，不标记成功 |
| 401/403 | 演示身份缺失/非管理员 | 永久失败，提示配置问题 |
| 404 | 教室不存在 | 永久失败 |
| 409 | 同编号参数不同，或该时段已有个人预约 | 永久失败，需人工协调 |
| 422 | 时间格式/区间非法 | 永久失败 |
| 503 | M1 暂时不可用 | 可重试 |

M1 的责任：

- 同一 `(source, external_id)` 只能有一条记录；重复调用不得创建第二条；
- 参数不同必须返回 409；
- 时段内存在个人预约时必须返回 409，不得静默覆盖或取消个人预约；
- 解除后的编号是**终态**。再次提交应返回 409；当前返回 200 + `active=0`，请 A 修正（见第 6 节）。

## 5. 释放占用（M2 → M1）

### DELETE `/api/integrations/restrictions/M2/{external_id}`

请求头：`X-Demo-User: admin`

- 200：已解除（包括本来就不存在，幂等）；
- 503：M1 暂时不可用，M2 进入 outbox 重试。

M2 在「已批准申请开始前撤销」时调用；只解除自己 `source=M2` 的记录，不影响 M3 维修限制。

## 6. 个人座位预约（仅演示/联调）

### POST `/api/reservations`

请求头：`X-Demo-User: student-a`

```json
{"seat_id": 1, "start": "2026-10-22T14:00:00", "end": "2026-10-22T16:00:00"}
```

M2 只在演示运维接口 `/api/v1/ops/m1-personal-booking` 中调用，用来证明：
整教室申请与个人预约冲突时，二级审批会被 409 拦下。M2 业务代码不依赖该接口。

## 7. M2 适配层规则

1. **时间**：M2 存 UTC-naive；调用 M1 前转 `Asia/Shanghai` naive，读取 M1 时间时反向转回 UTC-naive。
2. **教室 ID**：M2 API 对外是字符串，调用 M1 前转整数；非法 ID 直接永久失败。
3. **错误分类**：网络错误/5xx 可重试；4xx 和 `active=0` 永久失败，worker 直接置 `DEAD`，不做无意义重试。
4. **幂等键**：`application_id` 全局唯一；申请取消后不得用同一 ID 重新占用。
5. **不读 M1 数据库**，不复制 M1 的座位表结构。
