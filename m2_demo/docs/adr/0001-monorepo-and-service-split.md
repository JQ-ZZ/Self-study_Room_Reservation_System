# ADR-0001：单仓多服务 + 独立业务数据库

- 状态：提议
- 日期：2026-10-21
- 决策者：A / B / C（待确认）

## 背景

任务书要求模块之间通过网络调用，且每个人要有独立、可审查的提交记录。三仓库会导致
跨模块契约、迁移和 Compose 配置分散；单进程又会把跨模块调用退化成函数调用。

## 决策

1. 使用一个 monorepo，三人通过分支 + PR 提交。
2. M1 / M2 / M3 各自是独立可部署的 FastAPI 服务，通过 HTTP 调用。
3. 公共前端放在 `frontend/`，按路由分模块；公共能力（认证、通知、审计）由成员 C 的服务提供。
4. M2 在演示阶段自带一个 `m1_mock`，只用于验证调用和故障场景，不进入正式部署。

## 理由

- 满足「真实跨模块网络调用」和「每人独立提交」两条硬要求。
- 一套 Compose、一套 CI、一套迁移入口，降低三人协作成本。
- 服务边界清晰，模块数据库隔离在技术上可验证。

## 代价

- 需要维护接口契约和本地联调环境。
- CI 需要同时构建多个镜像。
- 仓库目录约定必须提前统一。

## 备选方案

- 三仓库：契约漂移风险高，不选。
- 模块化单体：无法证明网络调用，不选。
