# ADR-0004：数据库迁移由各模块拥有，流水线统一执行

- 状态：提议
- 日期：2026-10-21
- 决策者：A / B / C（待确认）

## 背景

任务书要求 schema 通过版本化迁移管理、空库可一次性恢复到最新、禁止手工改表，
且部署流水线中要能演示迁移。

## 决策

1. 每个服务独立维护 `alembic/` 目录和迁移链，业务负责人自己写业务表迁移。
2. 成员 B 负责迁移框架、命名规范、CI 检查和部署脚本，不代写 A/C 的业务表。
3. 规则：
   - 禁止 `Base.metadata.create_all()` 用于测试/生产环境（仅本地 SQLite 快速启动可开）；
   - 禁止手工改库；所有变更通过迁移提交；
   - 每个 PR 在空库上执行 `alembic upgrade head`；
   - 合并前执行 `alembic check`，确保模型与迁移无漂移；
   - 迁移只前进，生产回滚依靠向后兼容的 expand/contract 策略 + 镜像回退；
   - 删除列/表至少晚一个发布版本，给回滚留窗口。
4. 部署入口 `deploy/migrate.sh` 按依赖顺序执行各服务迁移，seed 与迁移分离、幂等。

## 理由

- 迁移所有权与代码所有权一致，避免 B 成为瓶颈。
- 空库迁移 + 漂移检查能在 CI 中自动发现「忘记提交迁移」。

## 代价

- 需要为三人约定目录和 CI 检查方式。
- 跨服务迁移顺序需要人工维护（当前 m1 → m2 → m3）。
