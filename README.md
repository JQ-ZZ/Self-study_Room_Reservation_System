# 栖学 · M1 自习座位预约 Demo

根据《软件过程管理PJ要求》中成员 A 的 M1 范围实现的可运行原型。M2/M3 仅提供联调入口，不包含队友的审批、工单模块。

## 快速运行

需要 Python 3.11+。在项目根目录打开终端：

```sh
python -m venv .venv
# Windows：.venv\Scripts\activate
# macOS / Linux：source .venv/bin/activate
python -m pip install -r requirements.txt
python -m uvicorn m1_demo.app:app --host 127.0.0.1 --port 8000
```

在自己的电脑浏览器打开 `http://127.0.0.1:8000`，API 文档为 `/docs`。Windows 也可双击 `启动演示.bat`（首次运行需要联网安装依赖）。云端运行的地址不等于你电脑的本地地址；下载后在自己的电脑运行即可。

```sh
python -m unittest discover -s tests -v
```

已验证环境：Python 3.12、FastAPI 0.141.1、Uvicorn 0.52.1。SQLite 为 Python 内置，无需数据库安装。数据库首次启动自动建表和初始化 3 个教室、72 个座位。数据保存在忽略文件 `m1_demo/demo.sqlite3`。停止服务后删除该文件可恢复干净的演示数据；不要在有重要数据时删除。

## 演示内容

- 座位查询：教室/区域、日期、整点时段、插座过滤；展示状态与来源。
- 创建预约：最多连续 4 小时、校验开放时间、禁止过去时间、座位与用户时间冲突。
- 我的预约：历史状态、取消、动态码签到、再次定位原教室选择新的预约。
- 后台任务：开始前 15 分钟提醒、开始后 10 分钟提醒、15 分钟未签到自动取消并记录违约与消息。后台每 2 秒执行，不依赖网页刷新。
- 管理：教室新增/编辑/停用/开放时间，座位新增/改编号/插座/停用，累计预约和签到/违约统计。
- 跨模块：M2/M3 限制来源、有效时间、幂等业务编号和单独释放，解除一个来源后其他来源仍然有效。

详细步骤见 [演示与接口说明](docs/M1演示与接口.md)。

## 与最终作业的边界

这是可操作的 M1 原型，不代表三人项目的最终交付：

1. 前端为无构建依赖的 HTML/CSS/JS，后端 FastAPI + SQLite，便于下载运行。统一技术栈后迁移到 Vue 3 / Element Plus、SQLAlchemy / Alembic / PostgreSQL。
2. 右上角切换的是**模拟身份**。`X-Demo-User` 不是登录认证，客户端可自行填写；只用于本地演示，禁止直接公开部署。管理员接口做身份检查，但正式版必须替换为成员 C 的真实认证/RBAC，跨模块调用改为服务认证。
3. SQLite 写事务串行化预约冲突检查与写入，真实数据库并发测试已覆盖两个请求争同一座位。正式 PostgreSQL 需实现数据库级排斥约束/锁策略，不能直接照搬 SQLite 的事务实现。
4. 时间统一为北京时间、不携带时区后缀。演示时钟可快进，偏移仅存在当前进程，重启归零。动态签到码按教室/日期生成，服务重启会更换密钥。正式版密钥需安全持久化并取消公开时间控制入口。
5. 当前单进程内置后台任务，生产需独立调度器与监控。站内通知是本模块的可验证实现，之后接成员 C 的公共通知。
6. 外部占用/维修遇到已有个人预约返回 409，需协调后取消再调用；不隐式取消学生预约。停用教室/座位阻止新预约，既有预约仍保留，管理员需另行处理。规则需三人确认。
7. 当前初始化版本为 SQLite `user_version=1`，不是最终 Alembic 迁移体系。Docker、CI/CD、审批发布与回滚等公共工程由成员 B 负责，本 demo 不声称已经完成。

源码、测试、演示说明已提供；不代替你们的独立提交、人工验收和 Review 记录。
